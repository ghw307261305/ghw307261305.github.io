要件定義需求定义Requirements definition日本では独立した工程で、成果物（要件定義書）に客先の承認印が要る。中国側は「需求分析」と一体で捉えることが多い。工程
基本設計 / 詳細設計概要设计 / 详细设计Basic design / Detailed design「外部設計 / 内部設計」と呼ぶ会社もある。どちらの成果物が契約範囲かを最初に確認する。工程
結合テスト集成测试Integration test日本の案件では「単体 → 結合 → 総合 → 受入」の四段が標準。中国側で「联调」と言うときは範囲が狭いことがある。工程
二次請け二包 / 二级分包Second-tier subcontractor元請け（一次）から仕事を受ける会社。客先と直接契約がないため、仕様変更の交渉は元請け経由になる。契約・商流
客先常駐驻场On-site assignment客先のオフィスと PC で作業する形態。持ち出せる情報が限られるため、ノウハウの蓄積は自分の記憶頼りになりやすい。契約・商流
工数人天 / 工时Man-days / Effort見積の単位。日本は「人月」「人日」、中国は「人天」が一般的。換算時は稼働日数の前提をそろえる。契約・商流
障害故障 / 生产事故Incident本番で起きた問題。「不具合（バグ）」とは区別され、報告書と再発防止策が求められる。運用・障害
本番リリース上线 / 生产发布Production releaseリリース判定会議を経て実施。判定の資料（テスト結果、影響範囲、切り戻し手順）が必須。運用・障害
切り戻し回滚Rollbackリリース失敗時に前の状態へ戻すこと。手順書に「誰が・何分以内に・どう判断するか」まで書く。運用・障害
組織（Salesforce）组织 / OrgOrgSalesforce の 1 契約単位の環境。「本番組織」「Sandbox」で区別する。会社組織の意味ではない。Salesforce
